## 5. สถาปัตยกรรมการจัดเก็บข้อมูลและโทเค็น (Storage & Security Policy)

1. **นโยบายการจัดเก็บโทเค็น (In-Memory Token Policy):**
   - `accessToken` และ `refreshToken` จัดเก็บในหน่วยความจำ JavaScript (In-Memory Module State)
   - ไม่บันทึกโทเค็นลงใน `localStorage` หรือ `cookie` เพื่อความปลอดภัยสูงสุดต่อการถูกขโมยผ่าน XSS
   - เมื่อผู้ใช้ Refresh หน้าเว็บหรือปิดแท็บ ระบบจะเข้าสู่หน้าจอที่ปลอดภัยและให้ผู้ใช้เลือกเข้าใช้งานบัญชีตัวอย่างได้อย่างสะดวกผ่าน One-Click Switcher
2. **การต่ออายุโทเค็นอัตโนมัติ (Single-Flight Refresh):**
   - เมื่อ API ตอบกลับ `401 Unauthorized` Client จะพักคำขอที่รออยู่และส่งคำขอ Refresh Token แบบ Single-Flight เพียงครั้งเดียว
   - เมื่อได้รับ Token คู่ใหม่ ระบบจะ Replay คำขอที่พักไว้โดยอัตโนมัติโดยที่ผู้ใช้ไม่สะดุด
3. **ขอบเขตข้อมูลใน LocalStorage:**
   - ใช้จัดเก็บเฉพาะตะกร้าสินค้าของผู้เยี่ยมชม (`bloom_guest_cart_v1`) และข้อมูลบันทึกสุขภาพออฟไลน์ที่มี Prefixed ด้วย User ID (`bloom_wellness_user_<id>`)
   - ไม่มีการจัดเก็บข้อมูลความลับ รหัสผ่าน หรือยอดเงินใน LocalStorage โดยเด็ดขาด

## 6. รายการบั๊กที่พบและการแก้ไขระหว่างรวมระบบ (Resolved Integration Issues)

1. **AUTH-08 เส้นทางการระงับผู้ใช้ของ Admin:**
   - *ปัญหา:* Script เรียก `POST /admin/users/:id/block` ซึ่งไม่มีในระบบ ส่งผลให้ได้ 404
   - *แก้ไข:* ปรับเป็น `PATCH /api/v1/admin/users/:id/status` พร้อมระบุฟิลด์ `{ blocked: boolean, reason: string }` ตาม schema backend
2. **ORD-14 ฟิลด์ข้อมูลการจัดส่งสินค้า:**
   - *ปัญหา:* Script ส่ง `{ trackingNumber: string }` แต่ Zod Schema ฝั่ง Server กำหนด `.strict()` รับ `{ carrier: string, tracking: string }` ส่งผลให้ได้ 400
   - *แก้ไข:* ปรับให้ส่งฟิลด์ `tracking` ตรงตาม Schema ของระบบ
3. **ORD-16 ฟิลด์ข้อมูลการตอบกลับรีวิว และการตรวจสอบการส่งมอบ:**
   - *ปัญหา:* Schema Backend รับ `{ text: string }` สำหรับตอบกลับรีวิว และต้องการสินค้าที่มีสถานะ `delivered` จึงจะอนุญาตให้รีวิว
   - *แก้ไข:* ปรับการส่ง payload ให้เป็น `{ text: string }` และเมื่อ ORD-14 ดำเนินการจัดส่งจนถึงรับสินค้าสำเร็จ รีวิวจึงส่งผ่านได้อย่างสมบูรณ์
4. **MGT-01 ขั้นตอนการยื่นขอเปิดร้านค้าใหม่:**
   - *ปัญหา:* เมื่อร้านค้าถูกปฏิเสธ หากต้องการส่งตรวจใหม่ต้องผ่านสถานะ `pending` เสียก่อน
   - *แก้ไข:* เชื่อมต่อเรียก `POST /api/v1/me/shop/resubmit` เพื่อส่งร้านค้ากลับเข้าคิวรออนุมัติ ก่อนที่ Admin จะทำการอนุมัติ
5. **MGT-05 ความซ้ำซ้อนของชื่อหมวดหมู่ในการทดสอบซ้ำ:**
   - *ปัญหา:* ฐานข้อมูล Postgres มี Unique Constraint บน `categories.name` การรันรอบสองส่งผลให้ได้ 409
   - *แก้ไข:* กำหนดชื่อหมวดหมู่ทดสอบแบบ dynamic timestamp เพื่อให้ชุดทดสอบรันซ้ำได้อย่างเป็นอิสระ
6. **MGT-06 ชื่อฟิลด์สรุปยอดขาย:**
   - *ปัญหา:* Script ตรวจหาฟิลด์ `netSalesCents` แต่ Backend สรุปข้อมูลในชื่อ `netMerchandiseCents` และ `collectedCents`
   - *แก้ไข:* ปรับ Assertion ให้ตรวจสอบฟิลด์ `netMerchandiseCents` ตรงตาม DTO จริงของระบบ
7. **FILE-03 & FILE-04 การปกปิดการมีอยู่ของสลิปโอนเงินส่วนบุคคล:**
   - *ปัญหา:* เมื่อผู้ใช้ที่ไม่มีสิทธิ์เรียกดูสลิป Server ปฏิเสธด้วย `404 NOT_FOUND` เพื่อป้องกันการสุ่มเจาะ ID
   - *แก้ไข:* ยอมรับสถานะความปลอดภัย `401/404` สำหรับ Unauthenticated และ `403/404` สำหรับ Cross-Account Isolation
